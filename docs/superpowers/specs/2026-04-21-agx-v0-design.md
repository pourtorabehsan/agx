# agx v0 — design

Date: 2026-04-21
Status: draft (brainstorm output)

## Purpose

`agx` runs a sandboxed Claude Code session in a Docker container so the agent can operate with `--dangerously-skip-permissions` against a workspace without risking the host. V0 is the minimum runtime that the eventual conductor/orchestrator will sit on top of — nothing more.

Everything beyond "start a container, run a prompt, exit" is explicitly deferred.

## Goals

- One Go binary, one command flow: prompt in → container runs Claude → result in a workspace dir on disk.
- Reproducible, isolated sandbox: no host credentials copied in, no host files reachable outside the workspace.
- Credentials (SSH, `gh`, `claude`) live in a shared container home that survives across runs.
- Each run gets its own named workspace, reusable on re-run, listable, removable.
- Headless by default; interactive TTY available via flag.

## Non-goals (deferred)

- Conductor / orchestrator loop.
- Knowledge base at `~/.agx/kb`.
- Slack / Notion / GitHub context adapters.
- Multi-repo workflow graph.
- Plan-and-review sub-agent pipelines.
- Concurrency guardrails (flock, per-container home overlay). Concurrent runs mostly work in practice; corruption risk is accepted for v0.
- Prebuilt image / registry publishing.
- Auto-cloning repos or auto-branching on the Go side. The agent inside does this using `$AGX_BRANCH_PREFIX`.
- `agx logs <name>` / transcript replay command.
- Cross-compilation for Linux, Windows support.

## CLI surface

```
agx bootstrap
agx run [flags] [prompt]
    -f, --file PATH       read prompt from file
        --name NAME       workspace name (default: slug of prompt; timestamp if prompt is empty)
    -i, --interactive     attach a TTY instead of headless
agx ls
agx rm <name> [<name>...]
```

### `agx run` prompt resolution

Precedence: `--file` > positional arg > stdin (only if stdin is not a TTY).

| Invocation                     | Mode        | Result                                                 |
|--------------------------------|-------------|--------------------------------------------------------|
| `agx run "prompt"`             | headless    | runs with prompt                                       |
| `agx run -f p.md`              | headless    | runs with file contents                                |
| `cat p.md \| agx run`          | headless    | runs with stdin                                        |
| `agx run -i`                   | interactive | blank Claude, attached TTY                             |
| `agx run -i "prompt"`          | interactive | seeded Claude, attached TTY                            |
| `agx run` (no source, no `-i`) | —           | error with usage                                       |

### Workspace name resolution

1. `--name NAME` if given.
2. Else, if the resolved prompt is non-empty, slug of the prompt (lowercased, alnum + hyphens, truncated to ~40 chars).
3. Else (blank interactive chat), ISO timestamp like `2026-04-21-143022`.

Existing workspace with that name → reused. No collision guardrail; a prompt with a colliding slug joins the existing workspace.

## Filesystem layout

```
<agx repo>/
├── cmd/agx/              # Go entrypoint
├── image/
│   ├── Dockerfile
│   ├── entrypoint.sh     # baked in as /usr/local/bin/agx-entrypoint
│   └── bootstrap.sh      # baked in as /usr/local/bin/agx-bootstrap
├── Makefile              # `make build` → docker build -t agx:latest image/
└── go.mod

~/.agx/
├── home/                 # shared HOME, mounted at /home/agx in every container
│   ├── .ssh/             # generated by bootstrap; not copied from host
│   ├── .claude/          # populated by `claude /login` during bootstrap
│   ├── .claude.json
│   ├── .config/gh/       # populated by `gh auth login` during bootstrap
│   ├── .gitconfig        # written by bootstrap (name/email prompted once)
│   └── .agxrc            # exports AGX_BRANCH_PREFIX and future settings
└── workspaces/
    └── <name>/           # per-run workdir, mounted at /workspace
        └── .agx/
            ├── prompt.txt    # this run's prompt
            └── session.log   # transcript (headless mode only)
```

The Go binary never shells out to `docker build`. Image is built via `make build`. If `agx:latest` is missing at run time, Docker errors and `agx` prints `run 'make build' first`.

The image's Dockerfile sets `CMD ["/usr/local/bin/agx-entrypoint"]` and leaves `ENTRYPOINT` unset. Default `docker run agx:latest` runs the entrypoint; `docker run agx:latest /usr/local/bin/agx-bootstrap` overrides CMD for bootstrap. No `--entrypoint` flag needed.

## Command flows

### `agx bootstrap`

Go side is a single `docker run`:

```
docker run --rm -it \
  -v ~/.agx/home:/home/agx \
  agx:latest \
  /usr/local/bin/agx-bootstrap
```

`bootstrap.sh` runs inside the container, each step idempotent:

1. Ensure `~/.ssh`, `~/.claude`, `~/.config/gh` exist.
2. If no `~/.ssh/id_ed25519`:
   - `ssh-keygen -t ed25519 -N '' -C "agx@$(hostname)" -f ~/.ssh/id_ed25519`.
   - Write `~/.ssh/config` pinning `IdentityFile`/`IdentitiesOnly` for `github.com`.
   - Print the pubkey + `https://github.com/settings/ssh/new`, pause for Enter.
3. If no `~/.config/gh/hosts.yml`: `gh auth login -p ssh --git-protocol ssh -w`.
4. If no `~/.claude/.credentials.json`: `claude /login` (exact command verified at implementation time).
5. If no `~/.gitconfig`: prompt for name + email, write `~/.gitconfig`.
6. If `~/.agxrc` missing or lacks `AGX_BRANCH_PREFIX`:
   - Default = `gh api user --jq .login`.
   - Prompt `Branch prefix for agent commits [<default>]:`.
   - Write `~/.agxrc` with `export AGX_BRANCH_PREFIX=<value>`.

Re-running skips any step that's already set up. No `--force` in v0.

### `agx run`

Go side:

1. Resolve prompt string (file > arg > stdin).
2. Resolve workspace name (flag > slug > timestamp). Create `~/.agx/workspaces/<name>/.agx/` if missing.
3. Write prompt to `<workspace>/.agx/prompt.txt` (empty file if blank-chat).
4. Exec docker:
   ```
   docker run --rm --init \
     [-it if --interactive] \
     -v ~/.agx/home:/home/agx \
     -v ~/.agx/workspaces/<name>:/workspace \
     -e AGX_MODE=headless|interactive \
     -e AGX_PROMPT_FILE=/workspace/.agx/prompt.txt \
     agx:latest
   ```
5. Stream stdout/stderr to the user's terminal. In headless mode, tee to `<workspace>/.agx/session.log`. In interactive mode, no tee (TTY).
6. Exit code = container exit code.

Container side (`entrypoint.sh`, the image's default CMD):

```sh
#!/usr/bin/env bash
set -euo pipefail
[ -f "$HOME/.agxrc" ] && . "$HOME/.agxrc"
cd /workspace
case "${AGX_MODE:-headless}" in
  headless)
    exec claude -p "$(cat "$AGX_PROMPT_FILE")" --dangerously-skip-permissions
    ;;
  interactive)
    if [ -s "$AGX_PROMPT_FILE" ]; then
      exec claude --dangerously-skip-permissions "$(cat "$AGX_PROMPT_FILE")"
    else
      exec claude --dangerously-skip-permissions
    fi
    ;;
esac
```

### `agx ls`

`os.ReadDir(~/.agx/workspaces)`, print names sorted alphabetically, one per line. No flags.

### `agx rm <name> [<name>...]`

For each name: `os.RemoveAll(~/.agx/workspaces/<name>)`. Errors if the path doesn't exist. No confirmation prompt.

## Internal structure

Small enough that formal packages are overkill for v0. Suggested layout inside `cmd/agx/`:

- `main.go` — subcommand dispatch.
- `bootstrap.go` — `agx bootstrap` (only builds the `docker run` argv and execs).
- `run.go` — `agx run` (prompt resolution, workspace resolution, docker exec, stream+tee).
- `workspace.go` — `agx ls`, `agx rm`, shared workspace path helpers.
- `paths.go` — `~/.agx/...` resolution.

One `go.mod`, one binary. Cross-compile deferred.

## Error handling

- Missing `agx:latest` image → docker's own error + `agx`'s hint to run `make build`.
- Missing `~/.agx/home` when running `agx run` → `agx`'s error: `run 'agx bootstrap' first`.
- Prompt source ambiguity (`--file` AND positional arg) → error, don't guess.
- `agx rm` on non-existent workspace → error listing which names didn't exist.
- All other docker / container errors propagate as the child's exit code.

## Testing

V0 is a thin wrapper. Unit tests for pure Go pieces:

- Prompt slug generation (edge cases: empty, very long, non-ASCII, all-punctuation).
- Prompt source resolution precedence.
- Workspace name resolution precedence.
- `~/.agx/...` path resolution respects `$HOME`.

Integration-ish (only when Docker is available locally, skipped in CI):

- `agx bootstrap` on an empty `~/.agx/home` exits successfully and populates expected files.
- `agx run "echo hi"` — actually, skip this: `claude -p "..."` requires real credentials and makes the test slow/flaky. Instead, a smoke test that substitutes a stub image (e.g., a Dockerfile that ENTRYPOINTs to `cat $AGX_PROMPT_FILE`) can verify mounts and env wiring without hitting Claude.

No test harness beyond `go test ./...` for v0.

## Open questions (implementation-time)

- Exact `claude` login invocation. `claude /login` is presumed; verify with the current Claude Code CLI at implementation time.
- Whether `claude -p` has changed its flag surface; confirm before wiring.
- `gh auth login` flag set — `-p ssh --git-protocol ssh -w` is the current best guess; verify.
- How to detect `claude` is finished vs blocked waiting for a tool permission that will never come (shouldn't happen under `--dangerously-skip-permissions`, but worth knowing the failure mode).
